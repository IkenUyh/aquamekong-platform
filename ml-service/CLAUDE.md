# ML service (`app/`)

- If `ENABLE_SCHEDULER` is set, the lifespan hook in `main.py` starts APScheduler jobs (`pipeline/scheduler.py`) every 15 minutes. The inbox job (`ingest/inbox.py`) imports files dropped in `INGEST_INBOX_DIR`. The mock crawler job (random data, only when `ENABLE_MOCK_CRAWLER`) runs crawler → preprocessor (`scale=False`, so real units go to the DB) → long format → insert into `measurements` against the CRAWLER sensors, and marks data processed in Redis only after the insert succeeds.
- **Data import** (`ingest/`, CLI `python -m app.ingest <file> [--dry-run]`): `parsers.py` detects the file format from its header (`FORMATS`; add a parser there for new RYNAN exports) and returns stations plus long-format measurements (`recorded_at` at 00:00 Asia/Ho_Chi_Minh; `*_lag_1d` columns go on `date − 1`; RYNAN water level is in cm and is stored in m). `stations.upsert_stations` creates stations and their CRAWLER device/sensors with the same SQL as Flyway V3, adds a default `salinity > 4` rule for newly created stations only (so rules an admin deleted are not recreated), and deletes the 6 demo stations (CASCADE). `loader.import_file` inserts in one transaction, with an `unnest` insert per 5000-row chunk and `ON CONFLICT (sensor_id, recorded_at) DO NOTHING`. `seed.seed_if_empty` (a one-off scheduler job when `SEED_DATA_URL` is set) downloads that file, turning a Google Drive share link into a direct download, and imports it only when no non-demo station has measurements. The RYNAN data is not committed because the repo is public. The backend `MeasurementPoller` ignores rows older than `app.telemetry.max-live-age` (3 days), so historical imports raise no alerts or SSE events.
- `services/predictor.py` caches results in Redis (`forecast:{station}:{days}:{date}`, but not simulated ones) and falls back in this order: the per-station Prophet model (trained by `/train`, `station_*_prophet.pkl` in `model_dir`), then the global Hybrid ARIMA-CNN (`hybrid_cnn.pth` plus the CSV dataset via `DataLoaderService.load_long_data()`), then a statistical trend from `measurements`, then simulated data. `/train` invalidates that station's cache. `load_raw_data()` is the ST-GNN pivot format, so don't use it for the hybrid model.
- Routes are plain `def` (FastAPI runs them in a threadpool) because they do blocking torch/ARIMA/SQL work. DB and Redis clients are shared singletons (`app/db.py`, `app/cache.py`). `db.py` forces the `psycopg2` driver because SQLAlchemy 2.1 defaults to psycopg v3.
