# ML service (`app/`)

- If `ENABLE_SCHEDULER` is set, the lifespan hook in `main.py` starts APScheduler jobs (`pipeline/scheduler.py`) every 15 minutes. The inbox job (`ingest/inbox.py`) imports files dropped in `INGEST_INBOX_DIR`. The mock crawler job (random data, only when `ENABLE_MOCK_CRAWLER`) runs crawler → preprocessor (`scale=False`, so real units go to the DB) → long format → insert into `measurements` against the CRAWLER sensors, and marks data processed in Redis only after the insert succeeds.
- **Data import** (`ingest/`, CLI `python -m app.ingest <file> [--dry-run]`): `parsers.py` detects the file format from its header (`FORMATS`; add a parser there for new RYNAN exports) and returns stations plus long-format measurements (`recorded_at` at 00:00 Asia/Ho_Chi_Minh; `*_lag_1d` columns go on `date − 1`; RYNAN water level is in cm and is stored in m). `stations.upsert_stations` creates stations and their CRAWLER device/sensors with the same SQL as Flyway V3, adds a default `salinity > 4` rule for newly created stations only (so rules an admin deleted are not recreated), and deletes the 6 demo stations (CASCADE). `loader.import_file` inserts in one transaction, with an `unnest` insert per 5000-row chunk and `ON CONFLICT (sensor_id, recorded_at) DO NOTHING`. `seed.seed_if_empty` (a one-off scheduler job when `SEED_DATA_URL` is set) downloads that file, turning a Google Drive share link into a direct download, and imports it only when no non-demo station has measurements. The RYNAN data is not committed because the repo is public. Format `rynan_raw` (`rynan_YYYY-MM-DD.csv`, rows `station_code, recorded_at, metric, value`, written by `scripts/rynan_fetch.py`, which the `rynan-daily.yml` GitHub workflow runs at 06:00 VN and uploads to Google Drive) keeps the file's timestamps and goes to `measurements` only, never the feature store (it lacks ST-GNN's rainfall/discharge/tide columns). `drive_sync.sync_drive` (hourly job when `GDRIVE_FOLDER_ID` + `GDRIVE_API_KEY` are set) downloads new or re-uploaded `rynan_*.csv` from that folder into the inbox, tracking `ingest:drive:<id>` = modifiedTime in Redis, and skips the run when Redis is down. `RynanClient` logs in like the app (`/api/LoginCustomer`, password CryptoJS-AES-encrypted with `username[1:4]`, 24 h token) and reads the app's "month" charts (`GetChartAverageOfMonth`, `GetListDataChartAWDByMonth` with the station's `IDAWD`), one call per station per month; their `MaxSalinity` / `MaxWaterLevel` (cm) match `salinity_max` / `water_level_max` in the features file. The hourly chart API only allows the last 14 days for normal accounts (`ERR_000739`), so it is not used. The backend `MeasurementPoller` ignores rows older than `app.telemetry.max-live-age` (3 days), so historical imports raise no alerts or SSE events.
- **ST-GNN** (`stgnn/`): `python -m app.stgnn.install <dir>` installs the team's `st_gnn_horizon_{1,7}.pth` + scaler into `model_dir/stgnn/` (`h{n}.pth` + `meta.json`). It checks the scaler pickle's globals with `pickletools` before `joblib.load`, requires the scaler to match one rebuilt from the feature store, and stores the test-split scores (overall and per station, vs naive). `stgnn/forecaster.py` reads only `meta.json` and `weights_only` torch files, preprocesses with the same `DataLoaderService.load_raw_data()` as training (17 stations kept by its 50% filter; it refuses if the station list changes), runs the whole graph once per feature-store/weights change, and returns day +1 and +7 dated from the last data day (`data_end`). The feature store (`FEATURES_DIR`, `ingest/features_store.py`) gets every imported features file.
- `services/predictor.py` caches results in Redis (`forecast:{station}:{days}:{date}`, but not simulated ones) and falls back in this order: ST-GNN (stations in the model whose 7-day test MAE beats naive, `days_ahead <= 7`), the per-station Prophet model (trained by `/train`, `station_*_prophet.pkl` in `model_dir`), then the global Hybrid ARIMA-CNN (`hybrid_cnn.pth` plus the CSV dataset via `DataLoaderService.load_long_data()`), then a statistical trend from `measurements`, then simulated data. `/train` invalidates that station's cache. `load_raw_data()` is the ST-GNN pivot format, so don't use it for the hybrid model.
- Routes are plain `def` (FastAPI runs them in a threadpool) because they do blocking torch/ARIMA/SQL work. DB and Redis clients are shared singletons (`app/db.py`, `app/cache.py`). `db.py` forces the `psycopg2` driver because SQLAlchemy 2.1 defaults to psycopg v3.
