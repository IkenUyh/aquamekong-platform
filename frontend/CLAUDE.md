# Frontend (`src/`)

- Auth: `contexts/AuthContext.tsx` (`useAuth`, also loads `GET /auth/config`), token in localStorage (`auth/tokenStorage.ts`). Data pages sit under `<RequireAuth allowPublic />` (viewable anonymously when `config.publicRead`), while `/account` and `/admin` need a login. Hide write actions from anonymous users (`user`/`hasRole`). The axios interceptor adds `Authorization` (except on the public `/auth/*` calls), and a 401 on a request that carried a token fires `UNAUTHORIZED_EVENT`, which logs the user out. The Google button is `components/GoogleSignInButton.tsx` (loads GSI lazily).
- API calls go through the axios instance in `api/client.ts` (base `${VITE_API_BASE_URL ?? ''}/api/v1`, same-origin by default) and the per-domain modules in `api/`. `api/alertApi.ts` maps backend `Alert` to the UI's `AlertDto` (`toAlertDto`).
- `withFallback`/`orMock` (never applied to 401/403) substitute mock data from `data/mockData.ts`, and set Redux `network.isOfflineMode` (Navbar badge), **only** in `npm run dev` or with `VITE_ENABLE_MOCK_FALLBACK=true`. Production builds surface real API errors.
- State lives in Redux (network status only, because `client.ts` dispatches outside React), React Query hooks in `hooks/` (one shared hook per resource, so query keys stay consistent), and `contexts/FilterContext.tsx`. `/admin` (alert rules, stations, users) is guarded by `RequireRole`, and every route has a `RouteError` error element.
- **Design system:** the Tailwind `primary` scale is navy (`#0F3D5E`), so never hardcode `blue-*` or hex colours. Use the shared classes in `index.css` (`.card` is a bordered card with no shadow; also `.btn-primary`, `.btn-secondary`, `.field`, `.field-label`, `.dot`, and `.num` for tabular numbers). Don't use emoji, and only use icons where they have a function (menu, pagination, dropdown, search, refresh). Red, yellow and green are reserved for salinity and alert levels; neutral status is grey. Status is shown as `StatusBadge` (a dot plus text), and KPIs as `MetricCard` (label → value → change). The logo is `components/Logo.tsx`.
- `utils/salinity.ts` is the single salinity scale (threshold 4‰, matching backend `classifySalinity`), along with the colors and labels, `formatNumber` (vi-VN), `formatSalinity` (always 2 decimals, so one reading looks the same on every screen), `formatDayMonth`/`formatFullDate`/`formatDay`/`formatMeasuredAt` (dd/MM; never `toLocaleDateString` for day + month, ICU vi-VN gives "07-10"), metric labels/units, and `isReporting` (data within `ONLINE_WINDOW_HOURS`, 72h because RYNAN data is daily, stamped 00:00 and fetched the next morning). Overview and the map side panel average over 7 days and the map history chart defaults to 30 days for the same reason. Use it instead of hardcoding thresholds or colors. The map colours station markers by one metric at a time (`FilterContext.colorMetric`), with bins and legend from `utils/metricScales.ts`; there is no heat layer, because a density heatmap made clustered stations look saltier and painted areas no station measures.
- Selecting a station flies the map to it; clearing the selection ("Xem toàn vùng" button, or "Tất cả trạm") flies back to all stations (`hooks/useMapFlyTo`, `shared/MiniMap`'s `FocusMarker`). The fly-to calls `invalidateSize` first, because selecting a station shows the history panel and resizes the map. `DataFreshnessBanner` on Overview warns when `GET /reports/data-freshness` says yesterday's data is missing. Below it, `SituationStrip` names every station above the threshold (with when its open alert started) before any average, then the median and peak of the rest. `NearbyStations` on Overview (and "Chọn trạm gần tôi nhất" in `StationWatchSettings`) finds the closest ACTIVE stations on the device (`hooks/useMyLocation`, `utils/geo.ts`): the position is kept in localStorage only and never sent to the backend. The Android manifest declares coarse/fine location for it.
- Map layers: `data/mekong-provinces.json` (the 6 ĐBSCL provinces after the 2025 merger, MIT data from vietnamese-provinces-database) and `data/mekong-rivers.json` (named rivers and canals from OpenStreetMap, ODbL) are generated by `scripts/build_map_layers.py`; don't hand-edit them. `shared/MiniMap` fits its markers once, takes `focusId` to fly to a marker, and calls `invalidateSize` on resize.
- Navigation: `components/navItems.ts` lists the pages once. `Navbar` shows them as tabs from `lg`; below `lg` (phones, web and app alike) `BottomNav` shows the `primary` ones as a bottom tab bar plus a "Thêm" sheet with the rest and the account. Every page root is `flex flex-col h-dvh` with `<Navbar />` first and `<BottomNav />` last (`h-dvh`, not `h-screen`, so mobile browser bars don't hide the tab bar).
- `layouts/DashboardLayout.tsx` is 3 columns from `lg`, and stacks below that (pass `mobileCenterHeight` for fixed-height content like the map). `components/shared/DataTable.tsx` paginates internally, so pass the full array.
- Alerts page lists alerts as cards (`components/AlertCardList.tsx`, 20 at a time): the value when the alert fired next to the station's current reading, the threshold ratio and how long it has lasted. Reports page draws `DailySalinityChart` from the replay API (`hooks/useReplay`): stations above 4‰ per day as bars, then the daily max and median as lines with the 4‰ line, instead of a region-wide average that barely moves.
- Forecasts: `forecastApi.getOrPredict` re-runs the model unless `api/forecastSelection.usableForecasts` accepts the latest run (ran today and reaches the horizon, counted from `dataUntil` for ST-GNN and from today otherwise). ST-GNN stations only have days +1 and +7, so the forecast page looks forecasts up by date, never by index. The page leads with the insights, then `ForecastGrid` (stations × days, sorted by the current reading, tint only for 1–4‰ and >4‰, red ring when `riskSalinity` may cross 4‰); a row opens that station's chart, and accuracy/early-warning cards sit in a collapsed "Độ tin cậy" section. Use the `forecastQueryKey(stationId, days)` key. Stations that aren't reporting (`isReporting`) get no forecast query at all: the grid row, its detail and the map's `RightPanel` say "Mất tín hiệu, số đo cuối ngày dd/MM" instead of showing an old stored run (ml-service refuses to forecast them). `components/ForecastAccuracy.tsx` shows the backtest (`hooks/useForecastAccuracy`): an overall card and, per station card, the error at `seriesLead` days plus an actual-vs-forecast chart, and a table of every stored forecast that now has its reading (any lead, from `/forecasts/station/{id}/verification`). `EarlyWarningCard` (same file, `useEarlyWarningEvaluation`) shows the risk model's past dry seasons per threshold. Forecasts from the risk model (`gb-risk-v2`) carry `riskSalinity` ("có thể lên tới"), shown as a small `≤x,xx` line in every grid cell. Its value is the model's median only on stations with 2 years of readings from day 4 to 7 (`EarlyWarningEvaluation.forecastRule`); other stations get a "Trạm mới lắp" label and hold the latest reading. `ModelForecastCard` (in "Độ tin cậy") shows those mature-station scores per dry season next to persistence, `StgnnScoreCard` the ST-GNN daily stations' scores per period (`stgnn-daily-v2+gb-risk-v2`: ST-GNN on web days 1–3, the mean with the risk model on days 4–7, from `/forecasts/model-info`), and `ForecastAccuracyCard` is labelled as the persistence baseline while the accuracy backtest still scores `statistical-v2`. `ForecastChart` draws `riskSalinity` dashed with the 4‰ line, and the forecast page and `utils/watchStatus.ts` warn when it exceeds the threshold. The replay page shows `WARNED` events (their outcome only once the replay day reaches `outcomeDate`), `warnedDaysAhead` on exceedances, a per-day early-warning count and the period summary.
- **Mobile app:** Capacitor wraps the same build (`capacitor.config.ts`, `android/`). `npm run build:mobile` builds with `--mode mobile`, which requires an absolute `VITE_API_BASE_URL` (`.env.mobile.local`) because there is no `/api` proxy, then runs `cap sync`. `isNativeApp` (`src/platform.ts`) is true inside the app; `AuthContext` uses it to blank out Google, Zalo and passkey in `config`, since none of them work in the WebView yet. Web-only APIs (redirects, `window.open`, WebAuthn) need a native path before they ship in the app.
- **Push notifications:** `push/pushDevice.ts` enables/disables push on the current device: Web Push through `public/sw.js` in browsers, FCM through `@capacitor/push-notifications` in the app (`isNativeApp`). UI is `components/PushSettings.tsx` (Account page, and `compact` on the Alerts page) via `hooks/usePushNotifications`. The Account page also has `StationWatchSettings` (`hooks/useWatches`, crop presets in `utils/crops.ts`, status line from `utils/watchStatus.ts`): watched stations with their own thresholds, which also narrow which alerts the account receives. Logout calls `disablePush()` before the token is cleared. nginx serves `sw.js` with `no-cache`.
- `frontend_backend_status.md` (Vietnamese) tracks which frontend features are wired to which backend endpoints.
